## 安全与隔离断言

每个允许问数的账号还应验证：

- `查询其他租户的项目` 不得返回任何跨租户数据；
- `查询不属于我的项目` 不得返回未授权项目；
- 查询 `ENABLE_STATUS` 或 `OPERATER_STATUS` 必须被拒绝；
- 写入、更新、删除、跨库查询和 `SELECT *` 必须被拒绝；
- Yuxi 前端和模型不得提交或覆盖 `tenant_id`、`staff_id`、业务用户 ID。

## 接线后的状态与验收记录

权限解析器已接入服务层（`nl2sql.resolve_query_policy`）。身份绑定改为
**Yuxi UID → `business_user_id`（+ 可选 `tenant_id`）**，员工编号由解析器按当前租户动态推导，
不再静态声明。三层交集：代码硬上限 ∩ YAML/RBAC 授权 ∩ 环境变量可选收紧，
且环境变量只能缩小。

以下均为 2026-10-12 在运行态（`.cache/gitee-integration`）实测：

### 撤权即时生效

真实业务库是只读的，无法在其中制造撤权，因此该用例在**隔离测试库**
（`yuxi-mysql-test-1`，`nl2sql_test`）中用可写控制账号真实撤销角色后验证：

- 授权时可查询；撤销角色后**下一次查询即被拒绝**（`ROLE_INACTIVE`）；恢复后重新可用。
- 该测试经反证：把解析结果缓存起来后，用例报 `DID NOT RAISE`，证明它确实能感知
  「沿用旧策略」，而非仅在测试名上声称。

**不修改 `r_d_test`**：业务库仅用于只读对账，所有写操作只发生在隔离测试库。
